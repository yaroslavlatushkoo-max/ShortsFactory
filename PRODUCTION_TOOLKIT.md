# PRODUCTION_TOOLKIT — blend3d

**Версия:** 1.0.0 (ноябрь 2026)
**Статус:** библиотека валидирована двумя реальными производствами и 22 автоматическими тестами.

`blend3d` — 3D-продакшн-слой ShortsFactory на Blender/Python для вертикальных
короткометражек (1080×1920, 30 fps, H.264/AAC). Он дополняет существующий
2D blocky-движок (Pillow): 2D-движок продолжает работать как прежде, blend3d
— отдельный трек для полнообъёмных сцен.

## Проблемы, которые решает каждый компонент

| Компонент | Проблема |
|---|---|
| `chars.py` | Персонажи «расползаются» между сценами → риг собирается из JSON-конфига одним вызовом, иерархия pivot'ов (бёдра/плечи/шея) зафиксирована, эмоции — 7 пресетов |
| `motion.py` | Ручной пошаговый кадр-за-кадром анимации → примитивы: ходьба от дистанции (не от времени — шаги не скользят), замах с контактом в точный кадр, падение, взгляд head_look с клампами |
| `production.CamRig` | Монтаж и движение камеры вручную → список ключей (кадр, позиция, цель, фокус), smoothstep, склейки соседними кадрами, органическая тряска, авто-кадрирование two-shot по позициям героев |
| `blocks.py` | Декорации вручную → куб-конструкторы (сетка пола, стены, руда с вкраплениями, деревья, факелы+свет, лава+свет) |
| `production.burst` | Частицы (поп блока, пыль, искры) вручную → один вызов + бейк по кадрам с гравитацией |
| `host.film_spec` | Сюжет только в голове → идея текстом → биты с таймингами → JSON (детерминированный планировщик; LLM-слой подключается сверху) |
| `host.render_job` | Ошибки команд рендера → валидированные argv-конструкторы (безопасно для jobs.py) |
| `host.qc.py` | Ручной просмотр как единственный контроль → автоматические гейты READY/PARTIAL/FAILED |
| `presets/*.json` | Настройки живут в голове → проверенные пресеты в декларативной форме |

## Как компоненты взаимодействуют

```
текст идеи ──▶ host.film_spec.plan_from_idea ──▶ FilmSpec (JSON)
                                                     │
                     host.render_job.build_*_argv ──▶ blender -b -P driver.py -- preview|render
                                                     │   (blender_lib: chars+blocks+motion+
                                                     │    production → сцена → бейк → кадры)
                     кадры + WAV ──▶ host.render_job.assemble_argv ──▶ ffmpeg ──▶ MP4
                                                     │
                     MP4/кадры/WAV ──▶ host.qc.verdict ──▶ READY / PARTIAL / FAILED
```

## Использование в следующем мультфильме

1. **Сюжет:** `spec = plan_from_idea("текст идеи")` (или FilmSpec вручную из LLM-слоя).
2. **Сцена:** скрипт-драйвер импортирует `blender_lib` (см. `examples/smoke_scene.py`
   и реальное производство `D:\Видео_Work\minecraft\scripts\film_*.py`):
   персонажи — `build_blocky_char(STEVE/ALEX/свой JSON-конфиг, ...)`;
   окружение — `cube_block/grass_block/tree/torch/lava_pool`;
   хореография — расписания кадров + `Swing/Path/FaceTrack` + бейк-цикл;
   камера — `CamRig(CAM_KEYS)` + `two_shot_override()` (авто-кадрирование по позициям героев).
3. **Рендер:** `host.render_job.build_render_argv(...)` → запуск → `frames_done()` для мониторинга.
4. **Сборка:** `host.render_job.assemble_argv(...)` → ffmpeg.
5. **QC:** `host.qc.verdict(frames_dir, wav, mp4_facts=...)` → READY/PARTIAL/FAILED.

## Проверено на реальных рендерах

- **«Алмаз» (Minecraft, 50 с, 1500 кадров, 1080×1920@30):** весь blender_lib в бою —
  2 персонажа (Стив/Алекс) с эмоциями, лава/факелы/руда, клатч-спасение, передачи
  предмета «из рук в руки» (мировой бейк по матрице руки), авто-кадрирование.
- **«Маленький садовник» (1110 кадров):** прародитель подхода — процедурный бейк,
  CamRig-склейки, частицы, титры (см. docs/PRODUCTION_ANALYSIS.md).

## Ключевые уроки, вшитые в код

1. **Пирамидальная иерархия и локальные координаты**: дочерние части авторуются
   в координатах СВОЕГО родителя (двойной учёт offset'а = «парящие части тела»).
2. **Scale-ключи перезаписывают строительный масштаб** — умножайте на базу
   (анизотропные объекты: трещины, лепестки, частицы — `_base_scale` в burst).
3. **Blender 5.2 портретный сенсор**: AUTO-fit даёт v-FOV ≈ 2·atan(10.125/lens) —
   авторские focal lengths подбирались эмпирически; не доверяйте «вертикальному 36мм».
4. **Точечные источники — на 0.1+ м от стен**, иначе свет замурован.
5. **Голова персонажа — child of head_p, лицо — child of head mesh**; поворот
   головы вращает лицо; клампы yaw/pitch обязательны.
6. **Тишина музыки в момент действия** (падение/клатч) усиливает удар сильнее любого свелла.

## Экспериментальное / ограничения

- `plan_from_idea` — детерминированный планировщик по ключевым словам: это
  нижний слой; LLM-планирование (Ollama уже есть в ShortsFactory) — следующий шаг
  (см. INTEGRATION_PLAN.md).
- Звуковой движок (`host.sound`) покрывает музыку/базовые SFX; фильм использует
  расширенный внешний скрипт (`audio_gen_mc.py`, читает timings.json) — по мере
  needs новые SFX-типы переносятся в пакет.
- Риг без изгибов (Minecraft-эстетика) — для органических персонажей нужен
  следующий уровень рига.
- Мировой бейк пропсов в руках (матрица руки пересчитана в python) работает,
  но при сложных позах требует ручной сверки кадров.
