# Master Roadmap M23+ — ShortsFactory

Дата: 2026-10-29. Основание: независимая валидация
[INDEPENDENT_VALIDATION_M17_M22_2026-10-29.md](INDEPENDENT_VALIDATION_M17_M22_2026-10-29.md)
и аудит [ANIMATION_AUDIT_2026-10-28.md](ANIMATION_AUDIT_2026-10-28.md).

Целевой продукт: оригинальный мультсериал с постоянными персонажами Milo и Nina,
вертикальные шорты 1080×1920@30, локально, бесплатно. Критерий успеха — не тесты
и не строки кода, а **визуально убедительная мультсцена** с надёжным пайплайном.

Отправная точка после M22: персонажи, ходьба, IK, эмоции, два актёра —
production-уровня; постановка (камера, окружение, звук персонажей, липсинк) —
уровень стенда. Самый короткий путь к «мультсцене»: звук → тайминги → камера →
окружение.

## M23 — Audio-first: единый источник таймингов речи

**Проблема.** Три несогласованных источника (валидация 3.2): рот — оценка
13 симв/с; субтитры — константа 1.4 с; аудио — реальные Piper-длительности.
Хвост тишины неуправляем; при коротком видео аудио может выйти за конец ролика.

**Почему сначала.** Все последующие постановочные миссии (камера на говорящем,
эмоции в момент речи, монтаж по репликам) зависят от честных таймингов. Дешевле
починить до M25, чем переделывать.

**Подход (двухпроходный):**
1. План → синтез всех реплик Piper **до** рендера (кэш TTS уже есть).
2. Реальные длительности WAV записываются в план/контекст как
   `voice_lines[i].duration_s`.
3. Субтитры строятся из тех же длительностей; константа 1.4 с удаляется.
4. Виземный трек растягивается по реальной длительности (функция `viseme_track`
   уже принимает duration — менять нужно только источник числа).
5. Хвост: последняя реплика + настраиваемый зазор (default 0.5 с) определяют
   либо длительность видео (видео подгоняется под звук), либо реплики подгоняются
   под длительность на этапе планирования.
6. Защита от выхода аудио за видео: `start + duration ≤ total` проверяется
   в `validate()` плана.

**Файлы:** `src/shortsfactory/generative/freeanim.py` (порядок шагов: TTS до render_plan),
`engine_dispatcher.py` (`_skinned_voice_lines` — брать реальные длительности),
`animation_plan.py` (поле duration у PlanVoiceLine + валидация), субтитры.

**DoD (измеримо):**
- субтитры: каждый блок выключается в пределах ±0.10 с от конца реального WAV;
- рот: последний кадр движения рта в пределах ±0.15 с от конца WAV (проверка по
  payload-треку);
- `abs(audio_len − video_len) ≤ 0.5 с` на тестовом прогоне; ноль реплик обрезано
  (ffprobe + ручное прослушивание);
- тест: unit на валидацию `start+duration ≤ total`; интеграционный прогон
  free-create skinned 8–10 с.

**Артефакты:** новый прогон `output/_quality_investigation/m23/`, сравнение
субтитров/аудио/визем до-после. **Риск:** изменение порядка шагов ломает
procedural-путь — там lip-sync уже встроен в движок; изменение должно касаться
только non-procedural ветки. Сложность: **M**.

## M24 — QC для 3D и честные отчёты

**Проблема:** валидация 3.3 — `character_walks`/`attachment_verified` дают ложные
false на 3D; `props_interacted` структурно false; `unique_frame_fraction 1.0`
захардкожен; 3D-метрики не пробрасываются в QC; фантомный `scene_path`.

**Задачи:**
1. Проброс `plan_diagnostics.json` (pose_error, mesh_motion, foot_contact,
   blank_frames, sec_per_frame) в FreeQC как первоклассные поля отчёта.
2. Гейты: общие (decode/streams/duration/audio/subtitles), 2D-специфика,
   3D-специфика: `foot_drift < 0.05`, `penetration < 0.01`, `blank_frames == 0`,
   `pose_error.passed`, `character_moves` (реальное смещение корня из payload).
   Неприменимые проверки для движка — статус `n/a` в отчёте, не false и не true.
3. `unique_frame_fraction` для non-procedural: считать по пустым кадрам
   (std-порог) из diagnostics, а не хардкод.
4. Починить `scene_path` (не подставлять путь, если движок его не вернул) —
   `freeanim.py:762`.
5. Опечатка «proceduralural» (`engine_dispatcher.py:414`).

**DoD:** QC-отчёт skinned-прогона содержит реальные 3D-метрики; ни одно поле не
false без причины; тесты: unit на классификацию гейтов по движку, интеграционный
прогон с проверкой отчёта. **Сложность: S–M.** **Риск:** низкий (отчётность,
не рендер).

## M25 — Камера и монтаж: шотовая система

**Проблема:** один статичный общий план; мимика и липсинк не видны; монтаж
отсутствует (визуальные баллы 3/10 и 2/10).

**Подход — план шотов, а не свободная камера** (в духе существующего 2D-сторияборда):
1. В `AnimationPlan` — список шотов: `{shot: wide|medium|close, start, end,
   subject: character|both, reason}`. Генерация на этапе плана: реплика →
   medium/close на говорящего; действие вдвоём → wide; реакция → close на
   слушающего (для M23-таймингов это тривиально).
2. Blender-шаблон: камера уже параметризована (`camera={"center","height"}`,
   `yaw` анфас/профиль, `fit_fraction`) — нужен монтажный склейщик: рендер
   сегментов одного payload с разными камерами + ffmpeg concat (перекодирование
   сегментов с совпадающими параметрами — бесшовно). Кадры одних и тех же сегментов
   кэшируются между камерами не нужно — сегменты не пересекаются.
3. Правила непрерывности: смена шота только на смене действия/реплики; ось
   диалога (Milo слева, Nina справа — раскладка уже фиксирована) не пересекать;
   hold ≥ 1.2 с на шот; без зумов.
4. Резервная композиция: широкий план — персонажи ≥ 55 % высоты кадра
   (сейчас ~40 %), потолок пустого неба обрезается.

**Файлы:** `animation_plan.py` (shots), `engine_dispatcher.py` (разбивка на
сегменты), `skinned_hero.py` (шаблон: приём camera/shot-сегментов), `freeanim.py`
(монтаж). **DoD:** диалоговый тестовый прогон: ≥3 шота, склейки только на
границах реплик/действий, говорящий в кадре с точностью до 0.3 с (по M23-таймингам),
композиционные минимумы проверены скриптом по кадрам. **Сложность: M.**
**Риски:** сшивки сегментов (усечь до целых кадров; перекодировать H.264 с
одинаковыми параметрами); рост времени рендера (монтаж из тех же кадров, рендер
не дублируется).

## M26 — Актёрская игра: текст → последовательность действий

**Проблема:** план строится rule-based шаблоном («найди камень» и «Майя и камень» —
два фиксированных сценария); LLM только расширяет идею. Сериал с разными историями
невозможен.

**Подход (поэтапно, с контролем качества):**
1. LLM-разметка: сценарий/история → структурированный список действий
   (по персонажам, с таймингами-долями и эмоциями), промпт с **закрытым словарём
   глаголов** `PLAN_ACTION_STATES` (иначе — ValueError по дизайну; LLM-выход
   валидируется, при невалидности — fallback на rule-based).
2. Постановочные примитивы поверх состояний: `look_at(other)`, `pause(0.4)`,
   реакция после действия другого персонажа (парные действия), ожидание перед
   действием (anticipation — уже есть в машине состояний как start).
3. Сверка: диалоговые реплики привязываются к talk-действиям (M23-тайминги),
   эмоции — к моментам реплик.

**Файлы:** `freeanim.py` (промпт+парсер+fallback), `animation_plan.py`,
`skinned_hero.py` (look_at — решить головой/глазами в IK-рамке). **Сложность: L**
(главный риск — нестабильность qwen2.5:7b, известная по STATUS проекта; поэтому
валидация+fallback обязательны до продвижения). **DoD:** 3 разных идеи → 3 разных
валидных плана (автотест на фиктивном LLM-ответе + живой прогон); ни один план не
упал в тихий fallback без пометки в отчёте.

## M27 — Голоса и звуковой дизайн

**Проблема:** один голос (dmitri) на Milo и Nina — диалог неразличим на слух;
звуковых эффектов нет.

**Задачи:** (1) второй ru-голос Piper для Nina из CC0/либеральных лицензий
(кандидаты из карточек Piper: ru_RU-irina-medium, ru_RU-ruslan-medium — **проверить
лицензию каждой карточки перед подключением**; правило проекта: NC-модели не
подключать); параметр voice у персонажа в `CharacterSpec`/плане. (2) Немного
событийных SFX (шаги, «во!») — только CC0-библиотеки или процедурная генерация
(numpy, как music.py в статическом конвейере). (3) Нормализация громкости
диалог + фон.

**Зависимость:** после M23 (тайминги). **DoD:** диалог двух голосов различим;
SFX с указанием лицензии в THIRD_PARTY_LICENSES.md; пиковый уровень ≤ −1 dBFS.
**Сложность: S.**

## M28 — Окружение и пропсы

**Проблема:** пустая сцена (серый пол + голубой фон); объекты истории («светящийся
камень») не существуют в кадре; сюжет держится на субтитрах.

**Подход (минимальный, параметрический):** каталог простых окружений
(лес/комната/улица: цвет фона, форма земли, 2–4 примитивных объекта-декора,
ключевой свет + небо) как декларативные JSON в духе `assets/voxel/catalog.json`;
пропсы истории — 1–2 меша на сцену с точкой на земле и событием attach к руке
(механизм событий уже есть в плане; verify для 3D — из M24). Эмиссивный материал
для «светящегося» объекта (EEVEE поддерживает).

**DoD:** тестовый прогон «лес + камень»: объект виден, attach проверен, кадр не
пустой по краям; композиция — персонажи ≥ 50 % высоты. **Сложность: M.**

## M29 — Кэш шотов и инкрементальный рендер

Рендер — доминирующая стоимость (163 с из 196 с полного прогона). После M25
(сегменты) естественно кэшировать отрендеренные сегменты по хешу (актёры+действия+
камера+окружение+параметры). Плюс: рендер preview 540×960 для итераций и финал
только по подтверждении. **Сложность: M.** Не начинать до стабилизации M23–M25.

## M30 — Сериал-слой (отложено)

Канон вселенной (персонажные карточки: внешность/характер/голос/отношения —
расширение `CharacterSpec` без ломки), эпизоды как последовательности сцен,
RU/EN-адаптация диалогов (адаптация, не перевод), метаданные. Начинать после
того, как одна 30–60-секундная сцена будет стабильно проходить визуальный
человеческий просмотр.

## Что не проводить пока (эксперименты, отложенные осознанно)

- **Пальцы/артикуляция кистей** — кисти-рукавицы приемлемы для стиля, крупные
  планы рук редки; вернуться после M25 (станет ясно по реальным кадрам).
- **Фонемный анализ аудио** (вместо графем) — только если после M23 остаточный
  рассинхрон рта будет заметен глазу; сильные локальные forced-alignment
  инструменты тяжелы и не нужны при реальных длительностях реплик.
- **Cycles/фотореалистичный рендер** — EEVEE закрывает стиль; 4 ГБ VRAM.
- **Облачные генеративные видео/платные API** — вне политики проекта.
- **Инкрементальные сети/диффузия для стилизации** — не при текущем железе.
