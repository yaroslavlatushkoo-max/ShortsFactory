# PRODUCTION_ANALYSIS — сравнительный разбор двух мультфильмов

**Производства:**
1. «Маленький садовник» (Gardener) — 37 с, 1110 кадров, 1 персонаж (Бобо), ночной остров-сад.
2. «Алмаз» (Minecraft) — 50 с, 1500 кадров, 2 персонажа (Стив и Алекс), пещера/шахта.

## Что перенесено из «Маленького садовника» в blend3d (как есть)

| Решение | Где живёт в тулките | Почему работает |
|---|---|---|
| Процедурный покадровый бейк (python-функция состояния → setattr + keyframe каждый кадр) | `motion.py` + бейк-цикл фильма | Полный контроль, детерминизм, никаких косых интерполяций |
| CamRig: ключи (кадр, позиция, цель, фокус) + smoothstep + look_at + микротряска | `production.CamRig` | Монтажные склейки соседними кадрами, «документальная» жизнь кадра |
| Скай-градиент ноды (Generated→Z→MapRange→Ramp) | `production.sky_gradient` | Дешёвая атмосфера без объёмников |
| Практический мотивированный свет у лица (фонарик-антенна → факел Алекса) | пресет `cave_night.face_warm` | Читаемость лица в тёмной сцене |
| Частицы-вспышки с гравитацией (burst/bake_burst) | `production.burst` | Поп блока, пыль, искры — один вызов |
| Титры/fade плоскостью, запарентованной к камере | `production.fade_plane_and_titles` | Надёжно на любом объектив |
| Нюанс: «тишина музыки в момент действия» | звуковой дизайн «Алмаза» | Падение/клатч ударяют сильнее |
| Эмодуляция через базовые scale + график эмоции | `chars.EMOTES/apply_emote` (перенос идеи с глаз Бобо на брови/зрачки/рот) | Дешёвые читаемые эмоции |

## Что нового появилось в Minecraft-фильме (и вошло в тулкит)

| Решение | Новизна |
|---|---|
| **Блочный риг-конструктор из JSON-конфига** (Стив/Алекс/любой humanoid; slim-вариант рук) | Любой новый персонаж = конфиг, не код |
| **Ходьба с фазой от дистанции** (не времени) | Шаги не скользят при разгоне/торможении |
| **Swing-расписание с контактом в точный кадр** (кирка/топор/любой инструмент) | Синхрон «звук-искра-контакт» |
| **hand_world(): мировая позиция руки для пропсов** | Передача предмета «из рук в руки» между персонажами (матрица руки пересчитана математически) |
| **FaceTrack + head_look с клампами** | Персонажи «играют» взглядами друг на друга/объекты |
| **Авто-кадрирование two-shot** по фактическим позициям героев (Twoshots-таблица) | Порт принципов авто-режиссуры C7 2D-движка в 3D |
| **Куб-строители окружения** (сетка пола, стены, руда с вкраплениями, деревья, факелы+свет, лава+свет) | Minecraft-локации за минуты |
| **Клатч-хореография** (падение → установка блока напарником → вытягивание) | Прототип «спасательного» бита |
| **Dramaturgic-подход**: 5 битов (завязка→находка→опасность→спасение→награда) с синхронной музыкой (пауза на действии) | Шаблон сценарной структуры для planner'а |

## Универсальное / специфичное

**Универсально (переносится на любые стили):** CamRig, скай-градиент, практический
свет, burst-частицы, титры/fade, QC-гейты, бейк-архитектура, hand_world-паттерн,
FaceTrack, «тишина в момент действия».

**Специфично для Minecraft/блочного стиля:** cube_block/ore/tree-строители,
блочный риг без изгибов, head-look вместо шеи, угловатая пластика прыжков.

**Специфично для стиля «Маленького садовника»:** скруглённые примитивы-персонажи,
сфера-голова с отдельно висящими глазами, hover-юбка, органический sway.

## Скорость и ресурсы (замеры)

| Метрика | Gardener | Minecraft «Алмаз» |
|---|---|---|
| Кадров | 1110 | 1500 |
| Рендер (RTX 3050 Ti, Eevee, 64 сэмпла, 1080×1920) | ~1.6 с/кадр, 30 мин | ~3.7–5 с/кадр, ~1.5–2 ч |
| Причина разницы | ~400 объектов, 3-4 источника | ~700+ объектов (блоки+вкрапления), 6-7 источников с тенями |

Оптимизации на будущее: чанковый рендер + resume (`host.render_job.frames_done`),
sample_step QC уже готовы; уменьшение числа источников с тенями.

## Ошибки, пойманные визуальными проверками (и вшитые в уроки)

1. Двойной учёт offset'а родителя → парящие части тела (2 итерации!).
2. Scale-ключи vs строительный масштаб (лепестки, алмаз, трещины, частицы).
3. Blender 5.2 портретный сенсор: v-FOV 2·atan(10.125/lens), не «вертикальные 36мм».
4. Факелы, замурованные в стену наполовину.
5. Титры за камерой (локальные оси камеры: вперёд = −Z).
6. Камера внутри стены/кроны дерева — проверка позиций относительно геометрии.
7. Смесь кириллицы/латиницы в путях (В vs B) — «тихие» дубликаты каталогов.
