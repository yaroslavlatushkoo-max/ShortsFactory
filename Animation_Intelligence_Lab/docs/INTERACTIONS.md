# INTERACTIONS

Подсистема захвата и передачи предметов (`interaction.py`). Каждое событие
имеет время, участников, предмет, список предусловий и ожидаемое состояние
после выполнения.

## Состояния предмета

```
free ──pickup/attach──► attached ──transfer──► transferring (у получателя)
  ▲                        │                        │
  └────── release/detach ◄─┴──────── release ───────┘
```

- `free` — предмет лежит в сцене без владельца;
- `approaching` — рука движется к предмету (резервируется сегментом reach);
- `attached` — удерживается персонажем относительно точки крепления;
- `transferring` — владение перешло получателю (переходный кадр);
- `released` — свободен после отпускания; позиция и скорость непрерывны
  с моментом отпускания.

## События и предусловия

| Событие | Предусловия | Результат |
|---|---|---|
| `pickup` / `attach` | предмет `free`, без владельца, актёр в пределах досягаемости (по умолчанию 0.2 ед. сцены), корректная точка крепления | `owner=actor`, `state=attached`, скорость обнулена |
| `transfer` | предмет принадлежит актёру, `receiver_id` задан и ≠ актёра | `owner=receiver`, `state=transferring`, мировая позиция сохранена |
| `detach` | предмет принадлежит актёру | владение снято, `state=released`, предмет остаётся на месте |
| `release` | предмет принадлежит актёру | как `detach`; свободный полёт наследует скорость |

Нарушенное предусловие поднимает `InteractionError` — данные никогда не
«тихо чинятся». Инвариант единоличного владения: в любой момент времени у
предмета не более одного владельца; попытка двух событий с разными
владельцами в один и тот же момент фиксируется валидатором как
`DOUBLE_OWNERSHIP` (severity `critical`).

## Порядок обработки

События сортируются по ключу `(time, kind_order, id)`, где kind_order:
pickup → attach → transfer → detach → release. Поэтому одновременные события
всегда обрабатываются детерминированно.

## Непрерывность при захвате/отпускании

- Захват: позиция предмета в мире не меняется (якорится к `attachment_point`),
  скорость гасится — это допущение модели «жёсткого крепления».
- Передача: мировая позиция сохраняется, меняется только владелец.
- Отпускание: предмет продолжает из той же точки; наследуется скорость актёра
  в рамках модели свободного движения.

## Реестр владения

`OwnershipLedger` хранит интервалы владения по каждому предмету и умеет
находить конфликты (два владельца в один момент или перезахват без
освобождения). Планировщик реплицирует события по этому реестру; несостоявшиеся
события не изменяют состояние и попадают в журнал планирования.

## Проверка досягаемости

`pickup` требует, чтобы актёр находился не дальше `prop_reach` (по умолчанию
0.20 нормализованных единиц) от предмета **в момент события** — позиция актёра
берётся из его траектории сегментов. Иначе событие не выполняется, а
валидатор помечает `TARGET_UNREACHABLE`.

Ограничения: модель кинематическая — нет силы хвата, проскальзывания,
одновременного владения на кадр перехода и физического свободного полёта
(после отпускания предмет не баллистически движется, а остаётся/наследует
скорость как значение).
