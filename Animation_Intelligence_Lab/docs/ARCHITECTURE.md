# ARCHITECTURE

## Обзор

Animation Intelligence Lab — конвейер: **сцена (JSON) → планировщик → план
движения → симулятор → диагностика/визуализация/экспорт**. Все алгоритмы
локальные и офлайн: NumPy + Pydantic + Matplotlib, без GPU и сетевых сервисов.

## Поток данных

```
SceneDescription (JSON)
        │  importer (exporter.import_scene)
        ▼
motion_planner.build_plan ──── interaction.apply_interaction (предусловия)
        │                      interaction.OwnershipLedger
        ▼
MotionPlan ──── validation.validate_plan ──── ValidationReport
        │
        ▼
Simulator.run ──── SimulationResult (кадры, журнал событий)
        │
        ├── visualization.render_diagnostic_png  → PNG
        ├── visualization.save_frames_csv        → CSV
        ├── exporter.export_json                 → версионированный JSON
        └── exporter.EngineAdapter               → данные стороннего движка
```

## Модули

| Модуль | Ответственность |
|---|---|
| `models.py` | Pydantic-модели всех сущностей, перекрёстные проверки ссылок, `SCHEMA_VERSION` |
| `vectors.py` | векторная математика, конверсия нормализованные↔пиксели, easing, численные производные |
| `trajectories.py` | детерминированные кривые (linear/bezier3/waypoints/hold/arc), скорость, ускорение, непрерывность |
| `interpolation.py` | смешивание состояний персонажа, поз, вращений по короткой дуге |
| `pose_system.py` | библиотека поз, валидация против лимитов, зеркалирование, переходы |
| `rig_2d.py` | иерархический 2D-скелет, прямая кинематика, демо-человечек, точки крепления |
| `collision.py` | круги/AABB, пересечения, близость, границы сцены, досягаемость |
| `interaction.py` | pickup/attach/transfer/detach/release, предусловия, реестр владения |
| `state_machine.py` | 13 состояний, таблица переходов, авто- и событийные условия |
| `motion_planner.py` | сборка плана: непрерывность, таймлайны персонажей, реплика событий, keyframes |
| `simulation.py` | состояние в момент t, семплирование по FPS, детерминированный журнал событий |
| `validation.py` | 14 кодов проблем с severity/временем/субъектом/советом |
| `visualization.py` | PNG-диагностика, кадровые ленты, CSV-экспорт позиций |
| `exporter.py` | версионированный JSON, JSON Schema, round-trip импорт, интерфейс адаптеров |
| `fixtures.py` | демо-сцены: корректный handoff, простой проход, намеренно сломанный handoff |
| `cli.py` | Typer-команды: validate, simulate, plot, export, report, example, adapters |

## Принципы

1. **Детерминизм**: любая функция состояния — чистая функция времени; одинаковые
   входные данные дают побитово одинаковые планы, кадры и журналы.
2. **Отказ вместо «тихого ремонта»**: нарушенные предусловия взаимодействия и
   структурные ошибки поднимают исключения (`InteractionError`,
   `PlanningError`, `IllegalTransitionError`).
3. **Валидация как анализ данных**: анализатор читает фактическое содержимое
   плана (кадры, сегменты, события) — статус PASS возможен только когда
   проверки реально выполнены и не нашли проблем.
4. **Единицы явно**: нормализованные координаты `[0,1]`, секунды, градусы;
   метаданные единиц включены в каждый экспорт (`units`).

## Ограничения архитектуры

- 2D-кинематика без динамики: скорости и ускорения — оценки из траекторий,
  а не результат физической симуляции.
- События обрабатываются по порядку `(time, kind, id)`; одновременные события
  с конфликтующим владением помечаются как `DOUBLE_OWNERSHIP`.
- Визуализация диагностическая: скелетные фигурки, а не художественные
  персонажи.
