# KINEMATICS

## Координаты и единицы

- Нормализованная сцена: X и Y в `[0,1]`, начало — **левый верхний угол**,
  X вправо, Y **вниз** (экранная конвенция).
- Время — секунды; FPS задаётся параметром (по умолчанию 30).
- Повороты — градусы; 0° смотрит вправо (+X), положительное направление —
  **по часовой стрелке на экране** (следствие Y-вниз).
- Пиксели: только при визуализации,
  `vectors.normalized_to_pixels(p, width, height)` и обратная
  `pixels_to_normalized`. Пример: точка `(0.25, 0.75)` при 1920×1080 →
  `(480, 810)` px.

## Модель персонажа

Персонаж представлен корневой позицией (`CharacterState.position`), поворотом
и опциональным скелетом (`Rig2D`). Скелет — дерево суставов:

- `Joint.local_position` — смещение в системе родителя (нормализованные
  единицы персонажа);
- `Joint.rotation` — локальный поворот (градусы), наследуется по цепочке;
- `RotationLimits{min_deg, max_deg}` — допустимый диапазон;
- `length` — необязательная длина кости до следующего сустава.

Мировые координаты суставов вычисляются прямой кинематикой
(`Rig2D.world_positions`): смещение поворачивается в систему родителя,
повороты суммируются. `hand_world_position` переводит якорь рига в координаты
сцены с учётом корня и масштаба.

### Демонстрационный риг
`hip_center` → `torso` → `neck` → `head`; плечи/локти/кисти с обеих сторон;
бёдра/колени/стопы. Точки крепления предметов: `hand_r`, `hand_l`, `head`,
`torso`. Оценка досягаемости руки: `arm_reach(rig, side)` — сумма длин звеньев
цепи плечо→локоть→кисть (для демо-рига ≈ 0.3 единицы персонажа).

## Траектории

| Вид | Описание |
|---|---|
| `linear` | прямая с easing |
| `bezier3` | кубическая Безье, 1–2 контрольные точки |
| `waypoints` | прохождение через точки, линейно по участкам |
| `hold` | удержание стартовой позиции |
| `arc` | дуга через одну контрольную точку |

Easing: `linear`, `ease_in` (t²), `ease_out` (1−(1−t)²), `ease_in_out`
(косинусный). Скорость — центральная разность по позиции (шаг 1 мс,
ограничен длительностью сегмента); ускорение — разность скоростей.
`enforce_max_speed` возвращает минимальную длительность прохода при лимите.

## Непрерывность

Конечное состояние сегмента должно совпадать с начальным состоянием следующего
(допуск 1e-6 единиц). Разрыв фиксируется `continuity_gap` и попадает в отчёт
как `TRAJECTORY_DISCONTINUITY`. Пауза между сегментами допустима — персонаж
просто стоит в конечном состоянии предыдущего сегмента.

## Ограничения модели

- Нет физики, инерции, гравитации, баланса: прыжок — это траектория корня,
  а не результат динамики.
- IK нет: позы задаются углами суставов, досягаемость проверяется
  приближённо по длинам звеньев.
- Риг — плоский (2D): двусторонние цепочки моделируются сменой знака углов.
- Коллизии — примитивные круги и AABB, не «тело» персонажа.
- Система не рисует финальных художественных персонажей и не создаёт
  финальный мультфильм; она рассчитывает и проверяет движение в пределах
  описанной модели.
